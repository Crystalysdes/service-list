# Service List — бот-менеджер канала

Бот ведёт канал «Service List | Список сервисов в одном месте» в том же оформлении, что и сейчас. Он:
- **Принимает платные заявки.** Человек описывает сервис, модератор одобряет, человек оплачивает через CryptoBot, и сервис сам появляется в нужной ветке.
- **Продаёт опции:** топ-1/2/3, премиум-эмодзи перед названием и название из анимированных эмодзи-букв. Об окончании опции бот напоминает.
- **Принимает жалобы со скриншотами** и ведёт канал Scam list.
- **Сам убирает мёртвые ссылки.**
- **Хранит всё в базе.** Если канал заблокируют, бот за несколько минут перевыложит его в новом канале.
- **Проводит сделки через гаранта (Auto-garant).** Деньги покупателя замораживаются у бота, пока обе стороны не подтвердят; спор решает модератор; комиссия сервиса — 5%.

## Что умеет

**Пользователям.** Капча, выбор языка (RU/EN), затем меню. Капчу при первом /start проходят все, включая админов (админские команды работают и без неё). Над меню может быть видео, GIF или картинка (🧾 Шаблоны → 🎬 Заставка меню бота). Кнопки: «📋 Service List» во всю ширину, под ней «🛡 Auto-garant» и «💬 Chat» (эти три синие), остальные по две в ряд, без цвета:
- **📋 Service List** ведёт в канал, **💬 Chat** — в чат сообщества. Защита от ботов: в приватный канал и в подключённый чат (📡 Каналы → 💬 Чат сообщества) каждый получает **свою ссылку** — на минуту (⚙️ Настройки) и на один вход. Истекла — кнопка 🔄 (внизу, рядом с «Язык» и «Помощь») или /start. Публичный канал (@username) открывается по обычной ссылке, неподключённый чат — по ссылке из ⚙️ Настроек или строки «Chat:» главного поста. Ссылки в самом главном посте остаются постоянными.
- **🛡 Auto-garant** — всегда в меню: создать сделку, «Мои сделки», «Как это работает» (подробности ниже). Пока приём сделок выключен, экран говорит «скоро включим», а кнопки «Создать сделку» нет.
- **➕ Add service**: ветка → название → описание → ссылка → предпросмотр строки в точности как в канале → модерация → счёт CryptoBot → публикация и уведомление.
- **🗂 My services**: карточка сервиса со статистикой (место в ветке, топ, опции и сроки, статус ссылки, сколько оплачено).
  - Кнопки: топ-1/2/3 (если занято — очередь), эмодзи, эмодзи-название, продление, изменение через модерацию.
  - Отсюда же «🙋 Это мой сервис» — привязать импортированный сервис к себе.
- **🚫 Scam list** ведёт в канал скам-листа.
- **⚠️ Report service**: жалоба на сервис из списка. Нужны подробное описание (от 100 символов) и 1–10 скриншотов, без скриншотов жалоба не отправляется.

**Администраторам** (`/admin`):
- **Мастер первого запуска.**
- **📥 Заявки.** Одобрить, 🎁 одобрить бесплатно (сервис публикуется сразу, без счёта; только админы), отклонить, исправить, забанить.
- **⚠️ Жалобы.** Дела со скриншотами.
  - В скам-лист: черновик карточки с выбором скринов, можно сразу забанить все сервисы владельца.
  - Отклонить, запросить ответ владельца, забанить заявителя.
- **🚫 Скам-лист.** Правка записей, снятие записи с возвратом сервиса, ручное добавление.
- **⛔️ Чёрный список.**
- **🗂 Категории и 🧩 Сервисы.** Порядок, топ-позиции, свои цены, ручное добавление.
- **💵 Цены и сроки. 😀 Эмодзи и 🔤 Шрифты** (каталог премиум-эмодзи и наборы букв).
- **🧾 Шаблоны** оформления, заставка меню, текст Scam list и **📌 главный пост канала**: обновлённый текст одной кнопкой (абзац про гаранта, «добавить свой сервис» — кнопкой под постом, ссылки Link/Chat на месте) или свой текст, кнопки под постом. **📡 Каналы и 🚚 Переезд** (там же зеркала).
- **🛡 Гарант:** сводка (баланс, заморожено, к выплате, комиссии), споры и вердикты, активные сделки, выплаты с ошибкой, поиск, 👥 чаты сделок; владельцу — настройки, приём сделок и выплаты.
- **📦 Импорт** текущего канала. **🔗 Ссылки** (мёртвые ссылки).
- **💾 Резерв. 🧾 Заказы.**
- **📊 Статистика**, в том числе по источникам трафика.
- **👥 Персонал** (owner, admin, moderator). **⚙️ Настройки. 🩺 Диагностика.**

## Что понадобится

1. **Бот и его токен** от [@BotFather](https://t.me/BotFather). К боту нужно привязать **коллекционный юзернейм с Fragment**: без него Telegram вырезает премиум-эмодзи из постов, которые бот публикует в канале. Бот это проверяет сам (🩺 Диагностика). Если юзернейма нет, посты с премиум-эмодзи он не трогает, чтобы не испортить оформление.
2. **Токен Crypto Pay**: [@CryptoBot](https://t.me/CryptoBot) → Crypto Pay → Create App. Для пробы подойдёт тестовая сеть: токен от [@CryptoTestnetBot](https://t.me/CryptoTestnetBot) и `CRYPTOPAY_TESTNET=true`.
3. **Сервер (VPS) с Docker**, лучше не в РФ: боту нужен доступ к `api.telegram.org`, `t.me` и `pay.crypt.bot`.
4. **Чаты в Telegram:**
   - приватный **служебный канал**: для бэкапов и технических операций;
   - **канал Scam list**;
   - **группа модераторов**: лучше с темами, отдельно «Заявки», «Жалобы», «Лог».

   Бот должен быть администратором во всех этих чатах и в основном канале с правами: публикация, редактирование и удаление сообщений, приглашение пользователей.
5. **Telegram ID владельцев**: их можно узнать, например, у [@userinfobot](https://t.me/userinfobot).
6. **Ссылки на эмодзи-паки** (`t.me/addemoji/...`): буквы для названий-из-эмодзи и эмодзи для каталога.
7. **Для гаранта (по желанию):**
   - **отдельное приложение Crypto Pay** только для денег сделок: [@CryptoBot](https://t.me/CryptoBot) → Crypto Pay → Create App, в его Security включите **Transfers**. Токен вводится в `servicelist config` (ESCROW_CRYPTOPAY_TOKEN); для пробы — приложение в [@CryptoTestnetBot](https://t.me/CryptoTestnetBot);
   - **группы для чатов сделок**: приватные супергруппы без тем с настройкой «История чата для новых участников: скрыта», без других админов. Советуем 20 и больше, минимум 5. Удобно создавать их со служебного аккаунта.

## Установка на сервер

Нужен чистый сервер с **Ubuntu 22.04/24.04 или Debian 12**.

1. **Подключитесь к серверу.** На Windows откройте PowerShell (на Mac/Linux — Терминал) и выполните `ssh root@IP_СЕРВЕРА`. Пароль root берётся из панели хостинга.
2. **Вставьте команду установки:**
   ```bash
   bash <(curl -fsSL https://raw.githubusercontent.com/Crystalysdes/service-list/claude/amazing-pasteur-j0islp/deploy/bootstrap.sh)
   ```
   Скрипт ставит Docker, скачивает бота в `/opt/service-list` и задаёт вопросы. Токены при вводе не видны — просто вставьте и нажмите Enter.
   - **Токен бота.** Скрипт проверит его и покажет @username бота.
   - **Telegram ID владельцев.** Свой ID подскажет [@userinfobot](https://t.me/userinfobot).
   - **Токен Crypto Pay.** Можно пропустить и добавить позже.
   - **Часовой пояс.**
   - **Пароль бэкапов.** По Enter скрипт создаст надёжный пароль и покажет его — **сохраните его** в менеджер паролей.

   Затем скрипт включает файрвол (открыт только SSH), собирает и запускает бота и печатает три секрета для GitHub.
3. **Добавьте секреты в GitHub.** Репозиторий → Settings → Secrets and variables → Actions → New repository secret. Создайте три секрета — `DEPLOY_HOST`, `DEPLOY_KNOWN_HOSTS`, `DEPLOY_SSH_KEY` — со значениями из вывода скрипта. Если SSH на сервере работает не на порту 22, скрипт напечатает и четвёртый секрет — `DEPLOY_PORT`.

После этого каждое изменение в ветке `claude/amazing-pasteur-j0islp` само проходит тесты в GitHub Actions и выкатывается на сервер.
- Ключ деплоя на сервере ограничен: им можно только обновить бота до коммита этой ветки. Ни консоли, ни других команд.
- Вручную обновить можно кнопкой «Run workflow» во вкладке Actions или командой `servicelist deploy` на сервере.

**Команды на сервере:**

| Команда | Что делает |
|---|---|
| `servicelist status` | Состояние контейнеров |
| `servicelist logs` | Журнал бота (выход — Ctrl+C) |
| `servicelist config` | Изменить токены, владельцев, пароль бэкапов; по Enter значения сохраняются |
| `servicelist restart` / `stop` / `start` | Перезапуск, остановка, запуск |
| `servicelist deploy` | Обновить до последней версии ветки |
| `servicelist backup` | Резервная копия прямо сейчас |
| `servicelist restore ФАЙЛ` | Восстановить копию в пустую базу |
| `servicelist deploy-key` | Новый ключ для GitHub; старый перестанет работать, обновите `DEPLOY_SSH_KEY` |

**После переустановки ОС или смены сервера** снова выполните команду установки и обновите в GitHub все три секрета: меняются и ключ сервера, и ключ деплоя.

**Без скрипта, вручную** (Docker уже установлен):
```bash
git clone https://github.com/Crystalysdes/service-list.git && cd service-list
cp .env.example .env && nano .env   # BOT_TOKEN, OWNER_IDS, POSTGRES_PASSWORD, CRYPTOPAY_TOKEN, BACKUP_PASSPHRASE, TIMEZONE
docker compose up -d --build
```

Миграции базы применяются при старте автоматически. Данные хранятся в томах Docker: `pgdata` для базы, `botdata` (`/data`) для медиа и архивов.

## Первая настройка (в Telegram)

Напишите боту `/admin` и пройдите мастер по пунктам.

Как подключать каналы и группу:
- На экране подключения бот сразу показывает кнопками каналы, где он администратор, или группы, где он состоит. Нажмите нужный.
- Если канала нет в списке, нажмите «📋 Выбрать канал» внизу экрана. Telegram покажет ваши каналы и сам добавит туда бота администратором с нужными правами.
- Ещё можно переслать пост оттуда или прислать @username / ID.

Telegram не даёт ботам узнать список своих чатов. Бот запоминает только те, куда его добавили или где изменили его права. Каналы, куда бота добавили раньше, выбирайте кнопкой «📋 Выбрать канал».

1. **📡 Каналы → 🗄 Служебный канал.**
2. **📡 Каналы → 👥 Группа модерации.** Сюда бот присылает заявки и жалобы. В группе с темами отправьте в нужных темах `/bind applications`, `/bind reports` и `/bind log`.
3. **📡 Каналы → ➕ Основной канал.**
4. **📡 Каналы → ➕ Канал Scam list.** По желанию там же **💬 Чат сообщества**: бот станет в нём админом с правом приглашать, и кнопка «💬 Chat» в меню начнёт выдавать личные ссылки.
5. **🩺 Диагностика.** Бот проверит права, премиум-эмодзи и лимиты Telegram.
6. **😀 Эмодзи и 🔤 Шрифты.** Пришлите ссылки на паки.
7. **📦 Импорт.**
   1. Бот читает канал, ничего в нём не меняя. Затем просит вписать названия сервисов, написанных эмодзи-буквами, показывает предпросмотр и отчёт.
   2. После «✅ Применить импорт»:
      - ⏳ задайте сроки уже оплаченных опций;
      - ⭐ при необходимости назначьте топ;
      - **🔗 Проверить ссылки** и **🙈 Скрыть неоткрывающиеся** уберут мёртвые ссылки.
8. **💵 Цены и сроки.**
9. **🩺 Диагностика → 🚀 В эфир.** С этого момента бот сам обновляет канал. Посты, которые совпали с базой, не меняются. У «[занять место]» меняется только адрес: теперь он ведёт в бота.
10. **🛡 Гарант** (когда будете готовы):
    1. задайте ESCROW_CRYPTOPAY_TOKEN в `servicelist config`;
    2. **👥 Чаты сделок → ➕ Добавить группу** для каждой группы — бот попросит нужные права и проверит настройки;
    3. в группе модерации отправьте `/bind deals` в теме для споров;
    4. проведите пробную сделку в тестовой сети между двумя аккаунтами, включая спор;
    5. **⚙️ Настройки гаранта** (комиссия, суммы, сроки) → **▶️ Включить приём сделок**. Бот сначала проверит, что приложение гаранта отдаёт баланс и переводы, а если нет — скажет, что поправить (обычно включить Transfers). Сначала лучше с небольшой максимальной суммой;
    6. **🧾 Шаблоны → 📌 Главный пост канала → ✨ Обновлённый вариант**, чтобы в посте появился абзац про гаранта.

## Как это работает

- **Оформление.** Посты собираются из шаблонов, извлечённых при импорте. Навигация всегда остаётся последним постом и закреплена.
  - Премиум-эмодзи нельзя сделать ссылкой (ограничение Telegram). Поэтому у названия из эмодзи-букв кликабельна метка «[тык.]» рядом, как сейчас у Crystalys.
  - Новые категории занимают место навигации, а навигация публикуется заново внизу. Удалять старые посты бот не может: Telegram разрешает это только в течение 48 часов.
  - «#навигация» в каждом посте категории — ссылка на пост навигации, «[занять место]» открывает бота сразу на добавлении в эту категорию.
  - **Ручная правка поста в канале.** Бот присылает уведомление:
    - «↩️ Вернуть как было» — бот сразу возвращает свою версию;
    - «✅ Оставить» — правка остаётся, пока не изменятся данные этого поста (сервисы, опции); тогда бот обновит пост и напишет об этом.

    После нажатия во всех копиях уведомления видно, что решили и кто.
- **Оплата.**
  - Счёт CryptoBot выставляется в USD, оплатить можно в USDT, TON или BTC.
  - Бот проверяет счета каждые 20 секунд и по кнопке «Я оплатил».
  - Оплата исполняется ровно один раз, даже если сигнал об оплате пришёл повторно.
  - Возвраты Crypto Pay через API не поддерживает: их делают вручную, а в 🧾 Заказах заказ отмечается как возвращённый.
- **Мёртвые ссылки.** Проверка раз в 12 часов, запросы растянуты по времени.
  - **Что считается «мёртвой» ссылкой:** страница t.me без названия (юзернейм или инвайт не существует), удалённый пост, ответ 404/410 или несуществующий домен. Ответы 403, 429, 5xx и таймауты считаются «неизвестно».
  - **Владелец узнаёт сразу:** при первой «мёртвой» проверке ему приходит «ссылка перестала открываться — замените её на новую» с кнопкой «🔗 Изменить ссылку».
  - **Когда сервис скрывается:** после 3 «мёртвых» проверок подряд за 48 часов и больше. Платному сервису сначала дают 72 часа сменить ссылку, владельцу приходит уведомление.
  - **Возврат:** если ссылка ожила в течение 30 дней, сервис возвращается сам.
  - **Предохранители:**
    - если эталонные ссылки проверились неправильно, «мёртвые» результаты не учитываются;
    - если новых «мёртвых» больше 15%, проход не применяется;
    - в обоих случаях админ получает сообщение.
  - **Смена названия по ссылке** (юзернейм мог занять кто-то другой) приходит админу на решение, и такой сервис сам не возвращается.
- **Жалобы.** Жалобы на один сервис собираются в одно дело. Бан в скам-лист:
  - сервис снимается с листа, опции аннулируются;
  - ссылка, @username и ID владельца попадают в чёрный список, повторную заявку бот отклонит;
  - в канале Scam list появляется карточка (ссылка не кликабельна), под ней скриншоты;
  - закреплён индекс: сначала описание канала на русском и английском («сервисы, которые Service List заблокировал за мошенничество»), затем список. Он публикуется сразу после подключения канала, даже пока список пуст.

## Auto-garant: сделки через гаранта

- **Как идёт сделка.**
  1. Одна сторона создаёт сделку: кто она (покупатель или продавец), что продаётся, условия, сумма в USDT, кто платит комиссию (покупатель, продавец или пополам — бот показывает суммы для каждого варианта), срок выполнения, по желанию @username второй стороны.
  2. Вторая сторона открывает ссылку-приглашение, видит условия и репутацию создателя (в боте с какого числа, успешные сделки, разные контрагенты, оборот, споры) и принимает. Если @username не был указан, создатель подтверждает, кто принял: утёкшая ссылка не пустит чужого.
  3. Покупатель платит счёт в USDT через @CryptoBot — деньги замораживаются у гаранта.
  4. Продавец нажимает «📦 Передал / выполнил», покупатель — «✅ Отпустить деньги» (подтверждение называет продавца с Telegram ID), и продавец сразу получает перевод в @CryptoBot.
- **Сроки.** Если покупатель молчит 72 часа после «Передал», деньги уходят продавцу сами (напоминания за 24 и 3 часа). Если продавец не успел к сроку, через 24 часа открывается спор. Все сроки и комиссия фиксируются в сделке при создании.
- **Отмена.** До оплаты — любой стороной. После оплаты — только по согласию обеих: покупатель получает сумму без комиссии. После оплаты 5% остаются сервису при любом исходе.
- **Спор.** Кнопка «⚠️ Спор» сразу замораживает сделку, причину бот спрашивает после. Модератор получает карточку (тема `/bind deals` или личка) и решает: всё продавцу, вернуть покупателю или разделить — всегда с причиной. Сделки от «порога только для админа» решают только админы; участник сделки не может её судить; о каждом вердикте бот сообщает владельцу.
- **Чат сделки.** Сразу после оплаты сделка получает свободную группу из пула: название «Сделка #N», закреплённая карточка, у каждой стороны своя ссылка.
  - Вход только по заявке: бот впускает покупателя, продавца и сотрудника, который запросил доступ из карточки сделки. Посторонних не пускает и исключает.
  - Каждое сообщение и правка сохраняются. Бот удаляет пересланные сообщения самого бота, сообщения других ботов и от имени каналов, ссылки на чеки и счета CryptoBot — платить можно только кнопкой в боте.
  - Через час после завершения стороны получают файл переписки, бот исключает всех, удаляет сообщения (Telegram разрешает только моложе 48 часов — поэтому история для новых участников скрыта) и возвращает группу в пул. Группа с посторонними внутри уходит на карантин.
  - Нет свободной группы — сделка ждёт в очереди и идёт в личке. Групп нет совсем — сделки просто идут в личке.
- **Деньги.**
  - Отдельное приложение Crypto Pay: деньги сделок не смешиваются с оплатами размещений.
  - Каждое решение по деньгам — одна транзакция в базе, поэтому «отпустить», автовыплата, отмена и вердикт одновременно дают ровно одну выплату.
  - Переводы идут с уникальным `spend_id`: Crypto Pay не проведёт один и тот же перевод дважды. Если ответ потерялся, бот сначала проверяет перевод по `spend_id` и только потом повторяет.
  - Получатель, ни разу не открывавший @CryptoBot, получает инструкцию, и бот повторяет перевод сам.
  - Раз в 10 минут сверка: баланс приложения должен покрывать всё замороженное и ждущее выплаты, иначе выплаты останавливаются и владелец получает тревогу. Неизвестные оплаченные счета и переводы тоже вызывают тревогу. Если Crypto Pay отказывает, тревога называет его ошибку и подсказывает, что поправить. После восстановления из копии выплаты ждут проверки владельца.
  - «Выплачено вручную» может отметить только владелец и только для выплаты с ошибкой, указав чек или перевод.
- **Кнопки и ссылки.** «🛡 Auto-garant» в меню есть всегда. Пока гарант принимает сделки, в каждом посте категории рядом с «#навигация» есть «#Авто-Гарант», а под главным постом — «🛡 Сделка с гарантом». Все ведут к созданию сделки.

## Резервные копии и переезд

- **Копии.**
  - **Когда:** каждый день в 04:00 по `TIMEZONE`, по кнопке в 💾 Резерве и перед переключением канала.
  - **Что внутри:** все таблицы, скриншоты и медиа, а также `pg_dump`. Токенов в архиве нет.
  - **Шифрование:** паролем `BACKUP_PASSPHRASE`.
  - **Где хранятся:** архив уходит в служебный канал, если он меньше 50 МБ, и лежит в `/data/backups`. Хранятся 14 ежедневных и 8 еженедельных копий.
- **Восстановление на новом сервере.** Запустите бота с тем же `BACKUP_PASSPHRASE` и восстановите копию одним из способов:
  - файл до 20 МБ пришлите боту: `/admin` → «♻️ Восстановить из резервной копии»;
  - любой размер: скопируйте файл на сервер (например, `scp servicelist-XXXX.slbk root@IP:/root/`) и выполните `servicelist restore /root/servicelist-XXXX.slbk`.

  Восстановление возможно только в пустую базу. После него запустите 🩺 Диагностику.
- **Новый токен.** Если сменился бот, привяжите к новому боту тот же Fragment-юзернейм и добавьте его админом в каналы. Пользователи продолжат работу после `/start`.
- **Канал заблокировали.** Бот сразу пришлёт тревогу с кнопкой. Дальше: 📡 Каналы → 🚚 Переезд → «Новый основной канал», и выберите новый канал так же, как при подключении.
  1. Бот опубликует всё в новом канале в том же оформлении, с навигацией и закрепом.
  2. Кнопка «Сделать основным» переключает меню и ссылки. Так же переносится канал Scam list.
  3. Для мгновенного переключения можно заранее держать синхронизируемое **зеркало** (📡 Каналы → ➕ Зеркало).

## Разработка

```bash
python3.12 -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
# для тестов нужен PostgreSQL 16: база servicelist_test, пользователь и пароль servicelist
# (или своя строка подключения в TEST_DATABASE_URL)
pytest
ruff check app tests && ruff format --check app tests
```

Тесты работают без сети: Telegram заменён эмулятором (`tests/faketg.py`), который воспроизводит поведение сервера. Эмулятор соблюдает лимит 100 сущностей, выдаёт «message is not modified», запрещает удалять посты старше 48 часов, умеет пересылку, закрепы и файлы. CryptoBot и загрузка страниц тоже подменены.

Устройство кода:
- `app/domain` — чистая логика: форматирование в UTF-16, разбор и отрисовка постов, ссылки, вердикты проверки ссылок.
- `app/services` — работа с базой и Telegram: синхронизация каналов, импорт, оплата, жалобы, скам-лист, проверка ссылок, бэкапы, переезд.
- `app/bot/routers` — диалоги.
